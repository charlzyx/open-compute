open-compute 0.3.1 fixes two upgrade failures on an existing 0.3.0 data directory. The instance can start in place. Tenant workers still have to be redeployed because each deployment identity includes the runtime system Worker manifest.

## Fixed

- Observability startup migrates `observability.sqlite` before applying `PRAGMA max_page_count`. A database already at its 1 GiB cap no longer fails migration V3 (`observability_invocations_received`) with `SQLITE_FULL`, which previously prevented the instance from starting and logged only `PLATFORM_UNAVAILABLE`.
- The system-owned dashboard rebuilds when the embedded runtime manifest changes. Reuse no longer depends only on the dashboard asset hash. A dashboard version created by another runtime build otherwise fails `RuntimeSource` verification with `VERSION_INVARIANT_VIOLATION`, and `/operator/` returns 500.

## Before you upgrade

- **Redeploy tenant workers.** This package binds the current system Worker manifest into every deployment descriptor, the same class of pre-1.0 identity break as 0.2.4 and 0.3.0. Existing workers keep their stored snapshots until redeployed; after redeploy they serve the current runtime. Upgrade preflight still admits a data directory that already passed 0.3.0, so the instance can start and operators can redeploy in place.
- Back up configuration, instance data, SQLite authorities, master keys, and object storage before replacing the binary. Keep one daemon owner per scope and data directory.
- No new control-plane migration is appended. Previously published migration filenames, order, and bytes are unchanged.
